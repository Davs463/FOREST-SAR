# Operación nocturna — Windows / Claude Code

## Antes de dormir (propietario)
1. Copiar este paquete a la raíz de una COPIA de trabajo del repo (no sobrescribir CLAUDE.md, docs o agents existentes sin comparar; fusionar reglas, la v4 prevalece para BosqueVivo). No ejecutar scripts de otros proyectos. Ideal VM Windows/WSL aislada, sin carpetas personales montadas, sin admin, sin llaves SSH ni credenciales de nube, sin conexiones a servicios de producción. Git rama feature ya existente, checkpoint de cambios propio. La carpeta por sí sola no aísla el shell. No activar bypass ni permitir Bash indiscriminado. No compartir máquina/sesión con otros proyectos. Desactivar suspensión manualmente si quieres continuidad, no script de cambios al sistema.
2. Confirmar CLI `claude --version`, `claude --help`, cuenta iniciada con método oficial. VS Code/Visual Studio extensión no implica CLI instalado. Si falta, instalar por instrucciones oficiales https://code.claude.com/docs/en/setup ; Git, Python 3.11/3.12 y Node LTS compatible con repo se instalan manualmente si faltan. No winget, npm global o admin automático. Revisa lockfile, scripts npm y dependencias. Ejecuta `preparar_bosquevivo.bat` desde raíz. Instala venv local y Playwright local; npm ci del proyecto solo mediante opción explícita `--app-deps` después de revisar scripts/lockfile (puede ejecutar lifecycle scripts). Si pnpm/yarn/u otro, usar lockfile propio manualmente antes. No cambiar package manager.
3. Búsqueda CMR es pública, pero descarga de productos puede requerir Earthdata Login y autorización de aplicaciones. Probar una descarga/subset antes de dormir, no contraseña en prompt. Si no tienes credenciales, no esperar: catálogo + UI sin datos, anotar bloqueo. Si Harmony tarda, guardar IDs y usar HDF5 solo si tamaño conocido y dentro del presupuesto. No usar credenciales de cuenta de compañeros sin permiso.
4. Ejecutar `git status` y crear rama: `git switch -c feature/bosquevivo-hackathon` (si ya existe, `git switch feature/bosquevivo-hackathon` tras revisar cambios). No correr en main/master. Guarda backup/checkpoint del trabajo. Verificar el `.gitignore` ya integrado en el repositorio limpio. Revisa `.claude/settings*`, hooks, MCP y configuraciones heredadas; no correr con hooks desconocidos. En CLI revisar `/permissions` y `/status` y comprobar que el proyecto se reconoce y los agentes aparecen (`/agents`). No usar instalador global original.
5. Ejecutar `iniciar_bosquevivo.bat` desde raíz. Usa modo `dontAsk` y archivo de permisos de sesión, max-turns 100; guarda salida. Acciones no aprobadas se deniegan en vez de quedarse esperando; no es aprobación automática universal. Reglas de proyecto/usuario/managed pueden modificar permisos efectivos. Revisa antes de ejecutar. El BAT comprueba la CLI, no garantiza cuota ni acceso a modelos. `Ctrl+C` detiene ejecución; no apagar PC ni cerrar consola. Si no soporta flags, actualizar CLI de forma manual o ejecutar interactivo con instrucciones. No poner `--dangerously-skip-permissions`. Si quieres modo auto soportado, elegirlo manualmente y revisar políticas, preferir VM. No puedo aprobar peticiones de tu CLI desde ChatGPT ni supervisarlo mientras duermes.
6. Si prefieres VS Code: pega una sola orden: “Lee CLAUDE.md y los documentos que referencia. Ejecuta los lotes P0 del backlog siguiendo el ciclo de los siete agentes. Integra el motor FOREST-SAR real, conserva diseño y usa comunidad demo. Registra permisos bloqueados y sigue tareas independientes. No despliegues ni hagas push. Deja HANDOFF y pruebas.” Configura permisos en Claude Code antes. `/departamento implementar BosqueVivo v4` es alternativa interactiva. El BAT usa prompt directo, no depende del slash command en print mode.

## Permisos y limitaciones
`dontAsk` deniega operaciones que pedirían permiso, salvo las explícitamente permitidas. `acceptEdits` acepta ediciones pero no garantiza comandos. Configuración de sesión `.claude/bosquevivo-session.json` permite Edit/Write según reglas de path y comandos específicos de proyecto. Los permisos Bash no son aislamiento: un script npm o Python permitido puede ejecutar código arbitrario con tu usuario; por eso usar VM/cuenta restringida, revisar dependencias y código antes de la sesión, y evitar secretos. La configuración deniega comandos destructivos comunes, no protege de todas las rutas indirectas. No desactivar sandbox ni ampliar allowlist automáticamente. En caso de bloqueo, el agente debe seguir otras tareas. No permitir instalaciones nuevas durante la noche fuera de la lista revisada. Si se usa WSL, adaptar paths de venv y comandos; el BAT es Windows. No ejecutar procesos con privilegios elevados.
